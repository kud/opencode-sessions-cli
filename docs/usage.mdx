Run it with no arguments:

```console
$ ocs
```

`opencode-ink` does the same thing. The list refreshes every three seconds on its own.

## The list

One row per session, with:

- the repo (the basename of the session's directory)
- the session title
- its state: `busy`, `retry` or `idle`
- its age, such as `now`, `12m`, `3h`, `4d` or `2w`
- whether the server is a headless instance or a window, and its port

Busy sessions come first, then retrying ones, then idle ones. Within each group the most recently updated session wins. A headless instance with no sessions yet still gets a row, titled `(no sessions yet)`, so you can stop it.

## Keys

| Key               | Action                                                           |
| ----------------- | ---------------------------------------------------------------- |
| `↑` `↓` / `j` `k` | Move                                                             |
| `↵`               | Attach to the session; quitting opencode returns you to the list |
| `x`               | Stop a headless instance (asks for `y` to confirm)               |
| `r`               | Refresh                                                          |
| `q`               | Quit                                                             |

While the stop confirmation is open, the other keys are ignored until you answer.

## Attaching

`↵` hands the terminal over to `opencode attach` for the selected session. When you quit opencode, you land back in the list.

## Stopping an instance

Press `x` on a headless row and confirm with `y`. On a window row it says so and does nothing: windows are never touched from here. The steps behind a stop are in [How it works](/projects/opencode-ink/docs/how-it-works#stopping).

## Demo flags

```console
$ ocs --mock
$ ocs --screen list
sessions
$ ocs --screen sessions
```

- `--mock` runs on fixtures, with no live data
- `--screen list` prints the screen names and exits
- `--screen <name>` opens directly on that screen; an unknown name is an error

These are handy for trying the interface without any opencode server running.
